Генератор дизайн-системы под конкретный продукт/страницу. Мирроринг подхода
«опиши продукт → получи обоснованную дизайн-систему». Не про ревью готового UI
(для этого `/audit-design`) и не про правки (`/polish`) — это про то, чтобы
задать характер интерфейса ДО написания кода.

Использование: `/design-system [описание продукта или страницы]`
(например: `/design-system лендинг подписки на корм` или без аргумента — тогда
берётся Симба-магазин по умолчанию).

## Порядок

1. **Определи контекст.** Тип продукта, аудитория, ключевые слова стиля, вайб.
   Для Симбы по умолчанию: интернет-магазин зоотоваров, тёплый/заботливый тон,
   мобайл-фёрст (см. `docs/design.md`).

2. **Задай регуляторы (dials).** Три параметра 1–10 из `docs/design.md`:
   `DESIGN_VARIANCE`, `MOTION_INTENSITY`, `VISUAL_DENSITY`. База Симбы: 4 / 3 / 5.
   Отклонения от базы — объявить вслух и обосновать.

3. **Reasoning «продукт → решение».** Выведи связку под контекст:
   - **Паттерн layout** — что за структура (Hero + Features + CTA, каталог-сетка, dashboard…).
   - **Стиль** — визуальный язык (для тёплого магазина: мягкий флэт, не глассморфизм/брутализм/AI-purple).
   - **Палитра** — от бренда, не стоковая. 1 акцент + нейтрали + семантика (успех/ошибка). Проверить контраст пар ≥ 4.5:1.
   - **Типографика** — пара «характерный заголовок + читаемый body», модульная шкала, вес для иерархии.
   - **Motion** — уровень из `MOTION_INTENSITY`, конкретные длительности/easing из `docs/motion.md`.
   - **Анти-паттерны под этот тип** — что именно НЕ делать здесь (свериться с `docs/design.md` anti-references и `docs/ux-guidelines.md`).

4. **Собери MASTER-спецификацию.** Самодостаточный блок с готовыми значениями
   (Tailwind-токены `fontFamily`/`colors`, cubic-bezier, длительности, шкала
   отступов) — чтобы `coder` мог применить без доугадывания. Дорогое суждение
   (вкус) тратится здесь один раз; исполнение — дешёвое.

5. **Pre-delivery чек-лист.** Приложи выжимку P1–P2 из `docs/ux-guidelines.md`
   (доступность + тач) как обязательные пункты приёмки.

## Правила

- Не генерировать «типовой красивый» интерфейс — держать характер бренда Симбы
  и не повторять AI-slop из `docs/design.md`.
- Не плодить абстракции и токены сверх нужного — минимальная палитра и шкала.
- Результат — спецификация (текст + токены), не код. Реализация — отдельным
  шагом через `coder` или `/feature`.
