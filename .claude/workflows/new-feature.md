# Воркфлоу: Новая фича

Процесс добавления новой функциональности в Симбу. Цепочка агентов (pipeline):
каждый агент передаёт результат следующему. Главный Claude только координирует.

## Шаги

### 1. Планирование → `planner`
- Декомпозировать задачу на шаги
- Определить какие файлы затронуты (`client/`, `admin/`, `server/`)
- Выявить риски и краевые случаи
- Критерии готовности («что значит сделано»)

### 2. Исследование → `researcher`
- Найти где живёт похожая логика (`server/src/routes/**`, `client/src/`)
- Понять текущие паттерны проекта — новая фича должна быть в том же стиле
- Найти точки интеграции (какой роут, какой store, какая Prisma-модель)
- Ограничение: не читать более 15 файлов, 3 подряд бесполезных — стоп

### 3. Архитектура (если фича трогает БД/API) → `architect`
- Изменения в `prisma/schema.prisma` (новые поля/модели)
- Контракт API: метод, путь, тело запроса, формат ответа `{ success, data, error }`
- Миграция: `npx prisma migrate dev --name <имя>`

### 4. Реализация → `coder`
- Backend: роут в `server/src/routes/**` с `preHandler: [authenticate]` где нужна авторизация
- Валидация входа через Zod на границе (тело запроса)
- Frontend: компонент/страница в стиле проекта, три состояния (loading / error / data)
- Цены — в копейках, бонусы — 5%, всё по бизнес-правилам (см. `docs/business-processes.md`)

### 5. Ревью (параллельно) → ревьюеры по типу файла
| Изменённые файлы | Агент |
|------------------|-------|
| `*.tsx` в `client/` или `admin/` | `react-reviewer` |
| `*.ts` в `server/` | `typescript-reviewer` |
| `prisma/schema.prisma`, миграции | `database-reviewer` |
| Роуты с данными пользователя | `security-auth-access` |

Затем `silent-failure-hunter` — проверка проглоченных ошибок и пустых catch.

### 6. Проверка
- `npm run build` в затронутых воркспейсах — сборка проходит
- Прогнать ключевой E2E-сценарий (`researcher` с заданием QA)
- Проверить что старые сценарии не сломались

- Пуш на `claude/greeting-nnz368`
- Не копить изменения — коммитить сразу после завершения фичи
