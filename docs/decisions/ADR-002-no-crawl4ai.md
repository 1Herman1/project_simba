# ADR-002: Не внедряем crawl4AI

**Дата:** 2026-07-25
**Статус:** Принято (отложено до появления запроса)

**Контекст:**
Рассматривали crawl4AI (Python, Playwright) как инструмент краулинга для
пополнения каталога товаров и мониторинга цен. Сверх встроенного WebFetch он
даёт: JS-рендеринг SPA, обход пагинации, батч по сотням URL, извлечение по
CSS-схеме без LLM, сессии и прокси.

**Решение:**
Не внедряем. Возвращаемся к вопросу только при явном запросе на мониторинг цен
конкурентов — и тогда как отдельный Docker-сервис за HTTP, вызываемый из
`automator`. Python в Node-код не тащить.

**Обоснование:**
- Нет подтверждённой боли: прайсы поставщиков зоотоваров приходят файлами
  (XLSX/YML/1С-выгрузка) — это `server/src/routes/admin/import.ts` уже умеет.
- Узкое место импорта — не парсинг, а **отсутствие upsert**: повторный прогон
  падает с «товар уже существует» на каждой строке, цены и остатки не обновляются.
- Эксплуатационная стоимость: Docker + Playwright ~1–2 ГБ на VPS ради одного
  нерешённого кейса.
- Мониторинг конкурентов — отдельный продукт (расписание, матчинг SKU, история
  цен, антибот) плюс правовая серая зона.

**Что делать вместо:**
Доработать `import.ts` до upsert по slug/sku с обновлением цены и остатка. Дешевле,
снимает реальную боль и является предусловием любой автоматизации импорта.
