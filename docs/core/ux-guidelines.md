# UX-гайдлайны (кросс-доменный чек-лист)

Полный проверочный список качества интерфейса по 10 категориям с приоритетами.
Дополняет, а не заменяет:
- **бренд и anti-slop** → `docs/core/design-principles.md` (источник истины по характеру Симбы);
- **анимацию** (easing, длительности, гейт «надо ли») → `docs/core/motion.md`;
- **моторику Apple** (отклик, материалы, interruptibility) → `docs/core/apple-patterns.md`.

Здесь — то, чего в наших доках не было: систематизированный чек-лист по
доступности, тач-взаимодействию, производительности, layout, формам, навигации
и данным. Ориентир web-first (React 18 + Vite + Tailwind); пункты, специфичные
для нативных приложений (наш скилл `react-native`), помечены `[native]`.

Адаптировано из методологии внешнего скилла ui-ux-pro-max (priority-framework),
переработано под наш стек и правила ревьюеров (порог уверенности 80%).

---

## Приоритеты (P1–P10)

Единая шкала важности дизайн-решений — ей пользуются `design-department` и
`design-reviewer` при ранжировании находок:

| Приоритет | Категория | Маппинг на наши уровни |
|-----------|-----------|------------------------|
| **P1–P2** | Доступность, Тач-взаимодействие | КРИТИЧНО |
| **P3–P5** | Производительность, Выбор стиля, Layout/адаптив | ВАЖНО |
| **P6–P8** | Типографика/цвет, Анимация, Формы/фидбек | ВАЖНО / КАЧЕСТВО |
| **P9–P10** | Навигация, Данные/графики | КАЧЕСТВО |

Правило: сначала чинится то, что выше по приоритету; внутри уровня — по leverage
(польза ÷ трудозатраты).

---

## 1. Доступность — P1 (КРИТИЧНО)

- **contrast** — текст ≥ 4.5:1, крупный (≥18px/bold) ≥ 3:1.
- **focus-states** — видимый focus-ring (2–4px) на интерактивных элементах; не убирать outline без замены.
- **alt-text** — осмысленный `alt` у смысловых картинок; пустой `alt=""` только у декоративных.
- **aria-labels** — `aria-label` у иконочных кнопок без текста.
- **keyboard-nav** — вся функциональность с клавиатуры, tab-order = визуальному порядку, нет keyboard-trap.
- **form-labels** — `<label for>` или обёртка; не placeholder вместо label.
- **heading-hierarchy** — последовательные h1→h6 без пропуска уровней.
- **color-not-only** — не передавать смысл только цветом (ошибка/успех — плюс иконка/текст).
- **aria-live-errors** — ошибки форм через `role="alert"` / `aria-live`, не только визуально.
- **reduced-motion** — уважать `prefers-reduced-motion` (детали → `docs/core/motion.md`).
- **skip-links** — «перейти к контенту» на страницах с тяжёлой навигацией.
- **dynamic-type** `[native]` — поддержка системного масштаба текста без обрезки.

## 2. Тач-взаимодействие — P2 (КРИТИЧНО)

- **touch-target-size** — минимум 44×44px (iOS) / 48×48dp (Android); расширять hit-area невидимым padding, если иконка меньше.
- **touch-spacing** — ≥ 8px зазор между кликабельными элементами.
- **hover-vs-tap** — важные действия по клику/тапу, не только на hover.
- **loading-buttons** — кнопка disabled во время запроса + спиннер; защита от двойного клика/сабмита.
- **cursor-pointer** — `cursor-pointer` на кликабельных (web).
- **tap-delay** — `touch-action: manipulation` против 300ms задержки (web).
- **press-feedback** — визуальный отклик на нажатие (ripple/opacity/scale 0.95–1.05).
- **safe-area** `[native]` — тач-таргеты вне выреза/Dynamic Island/gesture-bar.
- **standard-gestures** `[native]` — не переопределять системные жесты (swipe-back, pinch-zoom).

## 3. Производительность — P3 (ВАЖНО)

Зона агента `performance-optimizer`. Чек-лист:
- **image-optimization** — WebP/AVIF, `srcset/sizes`, ленивая загрузка не-критичных.
- **image-dimension** — `width/height` или `aspect-ratio` у `<img>` → нет CLS.
- **lazy-load-below-fold** — `loading="lazy"` для картинок ниже сгиба.
- **font-loading** — `font-display: swap/optional`; резерв места, чтобы не было FOIT/CLS.
- **bundle-splitting** — split по роутам (`React.lazy` + `Suspense`).
- **critical-css** — приоритет above-the-fold стилей.
- **content-jumping** — резервировать место под async-контент.
- **virtualize-lists** — виртуализация списков от 50+ элементов.
- **third-party-scripts** — async/defer, аудит лишних.
- **progressive-loading** — skeleton/shimmer вместо длинного спиннера для операций > 300ms–1s.

## 4. Выбор стиля — P4 (ВАЖНО)

- **style-match** — стиль под тип продукта (генератор → `/design-system`).
- **consistency** — один стиль на всех страницах.
- **no-emoji-icons** — SVG-иконки (Lucide/Heroicons), не эмодзи как структурные иконки.
- **icon-size-scale** — 20px для UI-контролов, 24px для навигации, 32px для смысловых акцентов; не произвольные размеры.
- **icon-fallback** — если в основном сете нет нужной иконки: сначала искать внутри того же сета, только потом добирать из второго, сохраняя толщину штриха, радиус и заливку.
- **icon-import-direct** — иконки импортировать прямым путём, не из barrel-файла (barrel тянет весь пакет в бандл).
- **palette-from-product** — палитра от продукта/бренда (для Симбы → `docs/core/design-principles.md`).
- **effects-match-style** — тени/blur/radius согласованы со стилем.
- **primary-action** — один primary-CTA на экран; вторичные визуально подчинены.
- **elevation-consistent** — единая шкала теней, не случайные значения.
- **dark-mode-pairing** — светлую/тёмную темы проектировать вместе (не инверсия).
- **icon-style-consistent** — один icon-set, единая толщина штриха и радиус.

## 5. Layout и адаптив — P5 (ВАЖНО)

- **viewport-meta** — `width=device-width, initial-scale=1`; не отключать zoom.
- **mobile-first** — от мобилы к десктопу (для Симбы — приоритет: большинство заходов с телефона).
- **breakpoint-consistency** — системные брейкпоинты (375/768/1024/1440).
- **readable-font-size** — body ≥ 16px на мобиле (иначе iOS авто-зум).
- **horizontal-scroll** — нет горизонтального скролла на мобиле; `max-width:100%` на img.
- **spacing-scale** — шкала 4/8px для padding/gap/секций.
- **container-width** — единый max-width текста (65–75ch / `max-w-prose`).
- **z-index-management** — определённая шкала z-index (0/10/20/40/100/1000), не произвольные значения.
- **viewport-units** — `min-h-dvh` вместо `100vh` на мобиле.
- **fixed-element-offset** — фикс-навбар/боттом-бар резервируют padding под контент.
- **visual-hierarchy** — иерархия через размер/отступ/контраст, не только цвет.

## 6. Типографика и цвет — P6 (ВАЖНО/КАЧЕСТВО)

Бренд-специфика Симбы → `docs/core/design-principles.md`. Общие правила:
- **line-height** — 1.5–1.75 для body.
- **line-length** — 65–75 символов на строку (мобайл 35–60).
- **font-pairing** — пара «характерный заголовок + читаемый body».
- **font-scale** — модульная шкала (12 14 16 18 24 32), не случайные размеры.
- **weight-hierarchy** — вес усиливает иерархию (600–700 заголовки / 400 body).
- **color-semantic** — семантические токены (primary/error/surface), не сырой hex по компонентам.
- **color-accessible-pairs** — пары fg/bg ≥ 4.5:1 (AA).
- **number-tabular** — табличные (моноширинные) цифры для цен, таблиц, таймеров.
- **contrast-readability** — тёмный текст на светлом (slate-900 на белом), не серый на сером.

## 7. Анимация — P7 (КАЧЕСТВО)

Полные правила (easing, длительности, гейт «надо ли анимировать») — в
`docs/core/motion.md` и `docs/core/apple-patterns.md`. Ключевое:
- Большинство UI-анимаций короче 300мс (дропдауны 150–250мс); крупные поверхности (модалки, шторки) 200–500мс — точные значения в `docs/core/motion.md`.
- `transform`/`opacity` только — не анимировать `width/height/top/left` (CLS).
- 1–2 ключевых элемента на вид максимум.
- ease-out на вход, ease-in на выход; выход ~60–70% длительности входа.
- анимации interruptible; не блокировать ввод во время анимации.
- stagger списков 30–50ms на элемент, не более ~8 подряд.

## 8. Формы и фидбек — P8 (КАЧЕСТВО)

- **input-labels** — видимый label у каждого поля.
- **error-placement** — ошибка под связанным полем.
- **error-clarity** — сообщение = причина + как исправить, не «Invalid input».
- **inline-validation** — валидация на blur, не на каждый keystroke.
- **submit-feedback** — загрузка → успех/ошибка после сабмита.
- **input-type-keyboard** — семантические типы (email/tel/number) → правильная клавиатура на мобиле.
- **password-toggle** — переключатель показа пароля.
- **required-indicators** — отметка обязательных полей.
- **empty-states** — понятный next step вместо белого экрана (для Симбы: пустая корзина/избранное).
- **toast-dismiss** — авто-скрытие тостов за 3–5с; тост не крадёт фокус (`aria-live="polite"`).
- **confirmation-dialogs** — подтверждение перед необратимым (удаление).
- **undo-support** — undo для деструктивных/массовых действий.
- **focus-management** — после ошибки сабмита авто-фокус на первое невалидное поле.

## 9. Навигация — P9 (КАЧЕСТВО)

- **nav-state-active** — текущая локация подсвечена (цвет/вес/индикатор).
- **nav-label-icon** — навигация с иконкой И текстом; не только иконки.
- **back-behavior** — предсказуемый back, сохраняет scroll/state.
- **deep-linking** — ключевые экраны достижимы по URL.
- **state-preservation** — назад восстанавливает scroll/фильтры/ввод.
- **breadcrumb-web** — хлебные крошки для иерархий от 3 уровней.
- **bottom-nav-limit** `[native]` — не более 5 пунктов в bottom-nav.
- **adaptive-navigation** — ≥1024px sidebar, мобила — bottom/top nav.
- **navigation-consistency** — размещение навигации одинаково на всех страницах.
- **destructive-nav-separation** — опасные действия (выход, удаление аккаунта) визуально отделены.

## 10. Данные и графики — P10 (КАЧЕСТВО)

Для дашбордов и аналитики (админка Симбы). Дизайн-система графиков → скилл `dataviz`.
- **chart-type** — тип графика под данные (тренд → линия, сравнение → бар, доля → pie/donut ≤ 5 категорий).
- **color-guidance** — доступные палитры; не только red/green (дальтонизм) — плюс паттерн/текстура.
- **data-table** — таблица-альтернатива для скринридеров.
- **legend-visible** — легенда рядом с графиком.
- **tooltip-on-interact** — тултипы с точными значениями (hover/tap), доступны с клавиатуры.
- **axis-labels** — оси с единицами и читаемой шкалой.
- **responsive-chart** — график перестраивается/упрощается на мобиле.
- **empty-data-state** / **loading-chart** — осмысленное пустое состояние и skeleton при загрузке.
- **number-formatting** — locale-aware числа/даты/валюты.
- **sortable-table** — сортировка с `aria-sort`.

---

## Как использовать

- **Перед UI-задачей** — свериться с релевантными категориями (P1–P2 всегда).
- **Ревью/аудит** — агент `design-reviewer` (визуал) и `design-department` (оркестрация всех UI-специалистов с единым отчётом по приоритетам).
- **Генерация новой дизайн-системы под продукт** — команда `/design-system`.
- **Финальный проход** — `/polish` (шлифовка) и `/preflight` (бинарный чек-лист).
