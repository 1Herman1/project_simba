# Apple-паттерны для веба

Прикладные паттерны Apple Design, применимые к веб-интерфейсам.
Только то, что реально используем — не полный HIG.

## 1. Interruptibility (главный принцип)

Никогда не блокировать ввод пользователя во время перехода — модалка
открывается, но клик уже проходит. Анимировать от ТЕКУЩЕГО значения на
экране, а не от целевого: если анимация прервана новым вводом (например,
пользователь снова кликнул тоггл до конца анимации), новая анимация должна
стартовать с текущей визуальной позиции, иначе будет рывок.

## 2. Отклик (kill latency)

- Подсвечивать кнопку на `pointerdown`, а не на `pointerup`/`click` — отклик
  ощущается мгновенным.
- Убрать искусственные задержки: debounce на клики, произвольные `setTimeout`
  перед реакцией UI, 300ms tap delay (не актуально в современных браузерах с
  `touch-action`, но проверить, что не эмулируется вручную).

## 3. Прямое манипулирование

При drag/swipe — элемент "приклеен" к указателю с учётом смещения захвата
(`grab offset`), а не прыгает к центру курсора. Использовать
`setPointerCapture()`, чтобы трекинг продолжался даже если указатель вышел за
границы элемента.

## 4. Симметричные пути

Если элемент вошёл справа — уходит вправо (не в произвольную сторону).
`transform-origin` указывает на источник появления. На обратимых переходах
(открыл/закрыл) — зеркалить easing: открытие `ease-out`, закрытие тоже
`ease-out`, но по обратной траектории, а не `ease-in`.

## 5. Rubber-banding

У границ скролла/свайпа сопротивление растёт прогрессивно (чем дальше тянешь
— тем сильнее сопротивление), а не жёсткий стоп на границе. В вебе — через
CSS `overscroll-behavior` для контроля поведения скролла на границах контента.

## 6. Материалы / полупрозрачность для иерархии

Nav, тулбары, шторки — как translucent-слои: `backdrop-filter: blur()` +
полупрозрачный фон, контент скроллится под ними. Чем больше поверхность
(например, полноэкранная шторка) — тем сильнее blur и глубже тень.

НИКОГДА не класть светлый полупрозрачный слой на светлый фон — читаемость
рушится (нет контраста между слоем и содержимым за ним). Текст поверх
translucent-слоя — не серый, а с повышенным контрастом и чуть более тяжёлым
начертанием (`font-medium`/`font-semibold` вместо `font-normal`).

```css
.toolbar-translucent {
  background: rgb(255 255 255 / 0.72);
  backdrop-filter: blur(20px) saturate(1.5);
  -webkit-backdrop-filter: blur(20px) saturate(1.5);
}
```

## 7. Типографика

- Трекинг (letter-spacing) зависит от размера: крупный дисплейный текст —
  negative tracking (`-0.02em`), body-текст — около `0`.
- Leading (line-height) обратно размеру: плотный на заголовках, свободнее на
  body-тексте.
- Иерархия строится весом + размером + leading, не только размером шрифта.
- Использовать `rem`/`em`, уважать пользовательский масштаб шрифта в браузере
  (не фиксировать `px` для текстовых размеров).

```css
.display-heading {
  font-size: clamp(2rem, 5vw + 1rem, 4.5rem);
  letter-spacing: -0.02em;
  line-height: 1.05;
  font-weight: 600;
}
```

## 8. Восемь принципов Apple HIG (кратко)

- **Purpose** — каждый элемент интерфейса служит понятной цели.
- **Agency** — пользователь управляет, интерфейс не решает за него.
- **Responsibility** — интерфейс честен насчёт последствий действий.
- **Familiarity** — использовать знакомые паттерны, не изобретать заново.
- **Flexibility** — интерфейс подстраивается под контекст (размер экрана, ввод).
- **Simplicity** (не минимализм) — убрать лишнее, но не в ущерб функции.
- **Craft** — внимание к деталям на каждом уровне.
- **Delight** — приятные неожиданности там, где это уместно (редкие события).

## 9. Wayfinding

Пользователь всегда должен понимать: где я / куда могу пойти / что там / как
выйти. Использовать прямые конкретные лейблы вместо общих: «Оплатить» вместо
«Далее», «Добавить в корзину» вместо «ОК», «Закрыть корзину» вместо «Назад».
