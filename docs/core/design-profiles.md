# Доменные профили дизайна

Универсальная база. Дополняет `docs/core/design-principles.md`: там —
**глобальные** запреты (действуют всегда), здесь — **доменные** (то, что в одном
типе продукта норма, а в другом дефект).

Принцип: сдержанная приглушённая палитра для SaaS — правильно; для интернет-
магазина — дефект («низкая энергия», «нет глубины»). Поэтому анти-паттерны и
рекомендации живут **в одной строке профиля** — их сила в связке «делай X, но
никогда не Y».

Использование: `/design-system` шаг 3 берёт профиль отсюда как отправную точку,
а суждение тратит только на отклонения и бренд-специфику.

## Таблица A. Профили продукта

### E-commerce (общий) — база интернет-магазина

| Параметр | Значение |
|---|---|
| **Паттерн** | Feature-Rich Showcase: Hero (value prop) → сетка карточек 4–6 → выгоды/юзкейсы → соцдоказательство → CTA |
| **Стиль** | Блочный, **с глубиной** — карточка товара отделена от фона тенью/границей |
| **Палитра** | Бренд-акцент + отдельный success-green (в наличии, добавлено в корзину) + urgency-акцент (остаток, срок доставки) |
| **Типографика** | Читаемый гротеск для тела, характерный заголовок; цены — табличные цифры |
| **Motion** | Hover-подъём карточки ~200мс + лёгкий scale; без авто-анимаций |
| **CTA** | Sticky в навбаре + повтор после блока фич + внизу |
| **❌ Анти-паттерны домена** | Плоский дизайн без глубины (карточки сливаются с фоном); текстовые простыни вместо визуальной иерархии; приглушённая палитра без энергии; слабые trust-сигналы |
| **Триггеры** | `if_conversion_focused` → добавить urgency-акцент (остаток, срок доставки)<br>`if_checkout` → сместиться в trust: гарантии, способы оплаты, **убрать отвлекающие CTA** |

### E-commerce Luxury — развилка, НЕ наш случай по умолчанию

Премиум-ветка требует другой типографики (elegant/refined serif), минимального
акцента, много воздуха и медленных анимаций 400–600мс.

Зафиксировано **как предупреждение**: при просьбе «сделай посолиднее» не
дрейфовать автоматически в премиальность — для массового магазина это снижает
конверсию и ломает тёплый тон. Переключаться только по явному решению.

### Pet / зоотовары — оттенок поверх E-commerce

Тёплая и слегка игривая палитра, профили питомцев, фотогалереи.

Ключевое: **тёплый/игривый регистр — осознанное решение домена, а не
«непрофессионально»**. Не выправлять зоомагазин в корпоративную стерильность.

### SaaS (общий)

| Параметр | Значение |
|---|---|
| **Паттерн** | Hero + Features + CTA |
| **Стиль** | Минимализм/Swiss, чистая сетка |
| **Палитра** | Trust-blue + контрастный акцент |
| **Типографика** | Профессиональная, жёсткая иерархия |
| **Motion** | Сдержанный hover 200–250мс |
| **❌ Анти-паттерны домена** | Избыточная анимация; тёмная тема по умолчанию |
| **Триггеры** | `if_data_heavy` → допустим плотный layout, glassmorphism<br>`if_ux_focused` → минимализм в приоритете |

### Дашборд / админка

| Параметр | Значение |
|---|---|
| **Паттерн** | Data-Dense: фильтры сверху → таблица/карточки метрик → детализация |
| **Стиль** | Плотный, VISUAL_DENSITY 7–9, 1px разделители |
| **Палитра** | Нейтрали + семантика статусов; цвет только смысловой |
| **Типографика** | Табличные (моноширинные) цифры обязательны |
| **❌ Анти-паттерны домена** | Декоративные тени и скругления «чтобы красиво»; воздух в ущерб плотности данных; анимация строк таблицы |

## Таблица B. Паттерны лендинга

| Паттерн | Порядок секций | CTA | Конверсионное правило |
|---|---|---|---|
| **Hero + Features + CTA** | Hero (заголовок + визуал) → value prop → 3–5 ключевых фич → CTA-секция → футер | Sticky в навбаре + внизу | Высокий контраст CTA к фону |
| **Pricing-focused** | Hero → 3 тарифа → таблица сравнения → FAQ → финальный CTA | В каждом тарифе + финальный | Подсветить средний тариф бейджем «популярный»; годовая скидка 20–30%; FAQ закрывает возражения |
| **Lead magnet + Form** | Hero → польза лид-магнита → превью → форма | Кнопка формы | **Полей в форме ≤ 3**; превью лид-магнита обязательно |
| **Hero + Testimonials + CTA** | Hero → польза → 3–5 отзывов → CTA | После соцдоказательства | Соцдоказательство **до** CTA; каждый отзыв с фото + имя + роль |
| **Before/After** | Hero → «было» → «стало» → как → CTA | После демонстрации | Контраст: приглушённое «до» vs яркое «после»; success-green на результате |

## Как применять

0. Если есть визуальная референция — сначала снять с неё значения (см.
   «Работа с референсами» в `design-principles.md`); профиль домена тогда
   служит проверкой на доменные дефекты, а не источником стиля.
1. Определи профиль продукта (таблица A) — для лендинга дополнительно паттерн из таблицы B.
2. Возьми оттуда паттерн, палитру-роли, motion, доменные анти-паттерны и триггеры.
3. Проверь триггеры: подходит ли условие (`if_checkout`, `if_data_heavy`) — если да, применяй override.
4. Наложи бренд проекта (`docs/projects/<проект>/brand.md`) — он всегда приоритетнее шаблона.
5. Сверься с глобальными anti-references (`design-principles.md`) — они действуют поверх любого профиля.
