## Технологический стек Симбы (реальный)

Важно для агента: проект Симба работает НЕ на Next.js.
Это React 18 + Vite (клиент) и Fastify (сервер). Не предлагать
для Симбы решения из мира Next.js — `app/api/**/route.ts`, `getServerSession`,
`NextRequest/NextResponse`, `next.config.js`, NextAuth, Vercel. Всё это не применимо.
Пути роутов: `server/src/routes/**`, аутентификация — свой OTP + JWT.

Общий стек по умолчанию для новых проектов описан в `docs/stack.md` — для Симбы
источник истины только этот раздел.

### Frontend (клиент + админка)
- Framework: React 18 + Vite (SPA, не Next.js, не App Router)
- Language: TypeScript
- Styling: Tailwind CSS
- Routing: React Router
- State: Zustand / React Context
- Forms: React Hook Form + Zod
- Воркспейсы: `client/` (магазин) и `admin/` (панель управления)

### Backend
- Runtime: Node.js
- API: Fastify (роуты в `server/src/routes/**`, защита через `preHandler`)
- ORM: Prisma
- Validation: Zod
- Auth: свой OTP (код на email/SMS) + JWT (сейчас в localStorage)

### База данных и хранилище
- Primary: PostgreSQL (self-hosted в Docker, не Supabase/Neon)
- Storage: MinIO (S3-совместимое, не Supabase Storage / AWS S3) — изображения товаров
- Cache/Queue: Redis не подключён (нет в docker-compose) — не предлагать BullMQ без установки Redis

### Инфраструктура
- Hosting: Timeweb VPS (не Vercel/Railway)
- Process manager: PM2
- Reverse proxy: Nginx
- Деплой: `git pull` на VPS → `prisma migrate deploy` → сборка → `pm2 reload`

## Старт каждого нового чата

При каждом новом чате с Гермесом Claude обязан:

1. Прочитать этот файл и CLAUDE.md перед началом работы
2. Прочитать самый свежий файл из `docs/session-log/` (сортировка по имени —
   дата в начале имени файла) — это резюме прошлой сессии, если папка не пуста
3. Поприветствовать: «Привет, Гермес! ...»
4. Напомнить текущую ветку: `claude/greeting-nnz368`, репо: `1Herman1/project_simba`
5. Если в прочитанном резюме есть раздел «Незапушенное» с реальными коммитами —
   первым делом попробовать их запушить, до начала новой работы

Токен (PAT) не запрашивать автоматически в начале каждого чата. Секрет нужен
только в момент реального пуша и только если окружение не даёт доступ само.
Запрашивать по факту — «сейчас буду пушить, нужен доступ», а не заранее.

## Резюме сессии

В конце сессии (пользователь прощается, просит закруглиться, явно говорит
«резюме» / «сохрани контекст» / «передать в другую сессию») — вызвать команду
`/summary`. Она пишет файл в `docs/session-log/` по фиксированному шаблону —
не пересказ диалога, а конкретика: что сделано, что отложено, незапушенные
коммиты, договорённости, следующий шаг.
