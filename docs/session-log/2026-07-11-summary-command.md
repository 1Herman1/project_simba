## Решения и договорённости
- Резюме сессий писать не как пересказ диалога, а как конкретный чеклист для
  следующей сессии — файлы, hash, статусы.
- При конфликте воркфлоу-файлов между параллельными сессиями — не тянуть
  одеяло, смотреть какая версия новее/полнее и брать её.
- Структура документации теперь двухслойная: `CLAUDE.md` = универсальные
  правила для любых проектов, `docs/project-simba.md` = специфика Симбы.
  Читать оба файла в начале сессии, не только CLAUDE.md.
